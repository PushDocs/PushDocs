# Кодстайл

## General

- Повторяющиеся значения с общим смыслом — пути, URL, значения по умолчанию, лимиты — выноси в именованные константы и переиспользуй через импорт. Не дублируй литерал в разных местах и не создавай отдельные локальные константы для одного и того же значения.
- Храни константу в модуле, который отвечает за соответствующее понятие. Если значение нужно нескольким пакетам, используй общий пакет в пределах разрешённых зависимостей из [проверки архитектуры](../scripts/check-architecture.mjs). Не создавай общий файл для несвязанных констант.
- Связанные значения объединяй в объект с `as const`; имена следуют существующему `camelCase`. Например, стандартные папки и публичные URL медиа заданы в `defaultMediaLocations` в [контрактах медиа](../packages/contracts/src/media-config.ts) и доступны через `@pushdocs/contracts`.
- Для фиксированного набора взаимоисключающих режимов, состояний или действий предпочитай строковый `enum`, когда он делает смысл значений явным и позволяет переиспользовать их в типах, условиях и схемах валидации. Например, режимы медиатеки определены общим `MediaInsertionMode`. Используй PascalCase для имени enum и его членов, задавай строковые значения явно. Не заменяй enum механически все строковые объединения: для разовой локальной структуры достаточно union, а для связанных настроек с разными значениями — объекта `as const`.
- В тестовых данных и ожидаемых результатах допустимы явные литералы, когда они фиксируют проверяемый контракт. Исторические миграции сохраняют собственные значения и не зависят от изменяемых констант приложения. Примеры конфигурации и документация также могут содержать буквальные пути.
- Не выноси в константы каждую строку или число механически: выделяй значения с самостоятельным смыслом или общей причиной изменения.

## Форматирование и проверки

Формат задаёт [biome.json](../biome.json): отступы пробелами, ширина строки 100 символов, двойные кавычки, обязательные точки с запятой и завершающие запятые.
