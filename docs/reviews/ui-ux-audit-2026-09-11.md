## Вывод

Основа редактора уже понятна. Основные оставшиеся проблемы связаны с контекстом проекта/ветки, зависимостью локальных действий от Git, последовательностью форм и обратной связью. Полный визуальный редизайн не нужен. Нужны единые правила поведения и проверки переходов между разделами.

## Высокий приоритет

### 1. Локальное сохранение всё ещё зависит от Git/VPN

Подтверждено по коду: GET и POST `/api/projects/[projectId]/workbench` создают `workbenchContext` с Git-провайдером до выбора операции. Поэтому сохранение текста, создание папки и перечитывание локального состояния требуют подготовки VPN. Локальное исправление страницы документов устраняет только первоначальную загрузку.

Исправление: отделить локальные операции от операций с провайдером во всех обработчиках. Подключаться к Git только для чтения отсутствующего файла, создания удалённой ветки и реальной синхронизации. Критерий: при недоступном VPN импортированная статья открывается, редактируется и сохраняется; отправка в Git показывает отдельную ошибку.

Источники: `apps/web/src/app/api/projects/[projectId]/workbench/route.ts`, `apps/web/src/lib/workbench.ts`.

### 2. Возврат через список проектов меняет рабочую ветку

Подтверждено по коду: карточка проекта ведёт на `/documents` без ветки; DocumentsPage выбирает основную ветку. Ссылка «Документы» в сайдбаре восстанавливает рабочую ветку и файл через `documentHref`. Два входа в один проект дают разный результат.

Исправление: единый переход «Продолжить работу» с восстановлением ветки и файла. Основная ветка используется только при первом открытии. Критерий: после работы в feature-ветке переход «Все проекты → проект» возвращает туда же.

Источники: `apps/web/src/app/(app)/projects/page.tsx`, `apps/web/src/components/project-context.tsx`.

### 3. Профиль и подключения выглядят настройками выбранного проекта, хотя действуют шире

Подтверждено по коду: профиль меняет текущую учётную запись; подключения загружаются через общий `listConnections()`. Они стоят в одном ряду с параметрами конкретного проекта и его участниками. Изменение общего подключения может затронуть несколько проектов.

Исправление: сохранить стабильные вкладки, но явно обозначить область действия: «Мой профиль», «Git-подключения» и список использующих подключение проектов в его модалке. Не добавлять ещё один уровень постоянного сайдбара. При нескольких проектах и отсутствии сохранённого выбора дать явный выбор проекта для проектных настроек.

Источники: `settings-navigation.tsx`, `connection-settings.tsx`, `settings-project.ts`.

### 4. «Обновить файлы» запускает синхронизацию с Git

Подтверждено по коду: кнопка проводника вызывает `mutate({ action: "sync" })`. Название выглядит как обновление списка, но ставится фоновая задача получения ветки из Git.

Исправление: назвать действие «Получить из Git», показать этап/результат и не оставлять пользователя гадать, обновился ли список. Одинаковое название и состояние во всех разделах.

Источники: `file-explorer.tsx`, `workbench.tsx`, обработчик `workbench/route.ts`.

## Следующий приоритет

### 5. Модалки имеют разные правила закрытия и сохранения

Создание подключения использует native dialog, редактирование — section с `aria-modal`. В последнем есть Escape и возврат фокуса, но нет ограничения Tab внутри окна. Закрытие форм может уничтожить введённые данные без предупреждения. В создании подключения нет общей блокировки закрытия во время сохранения.

Исправление: общий компонент модального окна с фокусом внутри, возвратом фокуса, единым Escape, состоянием отправки и проверкой несохранённых изменений. Проверить отдельно закрытие до/во время отправки и возврат с шага 2FA.

Источники: `create-connection-dialog.tsx`, `connection-card.tsx`, `critical-form.tsx`.

### 6. Шаг 2FA теряет название подтверждаемого действия

Подтверждено по коду: разные операции показывают одинаковые «Подтвердите действие» и «Подтвердить», скрывая исходную форму. Для удаления проекта, смены пароля и сохранения подключения это слишком мало контекста. На первой проверке состояния 2FA форма блокируется без отдельного текста ожидания.

Исправление: сохранить короткое описание действия и объекта на шаге кода: «Сохранить подключение Sendsay», «Удалить проект …». Показывать состояние запроса и переносить фокус в поле кода. Ненастроенную 2FA обозначать до заполнения большой формы, сохраняя возможность вернуться к введённым данным.

Источник: `critical-form.tsx`.

### 7. Сохранено в PushDocs, отправлено в Git и опубликовано — разные состояния

В браузере отображается «Черновик сохранён» и постоянная кнопка «К изменениям». Пояснение о локальном сохранении находится в title. Новый пользователь может принять сохранение за завершение работы.

Исправление: компактный счётчик неотправленных файлов рядом с «Изменениями»; на отправке показывать исходную/целевую ветку и связанный MR. После успеха дать конкретный результат со ссылкой. Не возвращать длинные постоянные объяснения над редактором.

Источники: `workbench.tsx`, `submit-changes.tsx`, `app-shell.tsx`.

### 8. В MR не хватает навигации при росте списка и признака свежести

В браузере открытие MR отделено от переключения ветки — это уже хорошо. По коду список линейный, без поиска и переключения открытые/закрытые/слитые; нет времени последнего обновления или явного обновления состояния. Большой список быстро станет неудобным.

Исправление: поиск по названию/номеру/ветке, фильтр состояния, компактное время актуальности и кнопка обновления. Виртуализация нужна при подтверждённом большом объёме, сама по себе она не заменяет поиск.

Источник: `apps/web/src/app/(app)/projects/[projectId]/reviews/page.tsx`.

### 9. Участники: справка важнее действия, а управление неполное

Подтверждено в браузере: вкладка «Участники», заголовок «Пользователи»; приглашение ниже большого блока прав ролей. По коду в списке нет смены роли/отзыва доступа и списка ожидающих приглашений; результат приглашения выводит ссылку без кнопки копирования.

Исправление: единое название «Участники», приглашение рядом с заголовком/списком, «Скопировать ссылку», отдельное состояние приглашений. Справку оставить всегда видимой, как просил пользователь, но сделать компактнее. Смена роли и отзыв доступа — отдельная функциональная задача с проверкой прав, а не только добавление кнопок.

Источник: `apps/web/src/app/(app)/projects/[projectId]/members/page.tsx`.

### 10. Добавление проекта требует знания внутренних параметров

По коду URL, короткий адрес, ветка и корень Docusaurus находятся в одной форме; slug вводится вручную, ветка — свободный текст. Ошибку настройки человек узнаёт поздно.

Исправление: после выбора подключения/репозитория подставлять название, slug, основную ветку; технические параметры раскрывать по необходимости. Показать проверку доступа и обнаруженного корня до импорта. Не пытаться скрыть настоящую ошибку подключения красивым загрузчиком.

Источник: `apps/web/src/app/(app)/projects/new/page.tsx`.

### 11. Поиск по содержимому охватывает не все видимые файлы

Подтверждено по реализации: `searchFiles` в режиме содержимого ищет только в переданных статьях md/mdx; текст JSON, TS и других файлов, показанных в проводнике, не ищется. Внутри режима есть подсказка «поиска в статьях», но ожидание VSCode подразумевает весь проект.

Исправление: либо явно назвать режим «Текст статей», либо реализовать поиск по всем доступным текстовым файлам с отображением области поиска. Не показывать «Файлы не найдены», если файл просто не входит в индекс.

Источник: `quick-open.tsx`.

### 12. Предпросмотр — локальная интерпретация, а не полная сборка сайта

Базовая проверенная статья отображается корректно: заголовки, таблицы, код и примечания. По коду используется ограниченный Markdown/MDX-рендерер, поэтому нельзя считать этот результат точной проверкой всех компонентов Docusaurus.

Исправление: сохранить простой «Просмотр», но при неподдержанном компоненте показывать локальную понятную заглушку и доступ к предпросмотру сайта/MR. Не возвращать глобальную техническую надпись над каждой статьёй.

Источники: `document-preview.tsx`, `preview-markdown.ts`, `reviews/page.tsx`.

## Что уже удачно и стоит сохранить

- Единое дерево файлов, выбор папки перед созданием, иконки с подсказками.
- Ограниченная высота редактора и проводника, собственная прокрутка.
- Свойства статьи сгруппированы по назначению и объясняют влияние на сайт.
- Создание нового файла сразу предлагает путь в текущей папке и выделяет имя.
- Просмотр MR не переключает рабочую ветку, для этого есть отдельная кнопка.
- Разделение локального diff и отправки изменений; подтверждение отката конкретного файла.
- Резервное сохранение текста и отдельные состояния ошибок сохранения уже предусмотрены.

## Рекомендуемый порядок

1. Устранить зависимость всех локальных операций от VPN; закрепить сохранение ветки при любом входе в проект.
2. Уточнить область настроек и результат Git-действий; унифицировать модалки и шаг подтверждения.
3. Привести участников и импорт проекта к коротким законченным сценариям.
4. Улучшить поиск/MR для больших проектов и провести отдельный клавиатурный и мобильный прогон.

Регрессионные проверки должны проходить путь пользователя: проект → ветка → настройки → документы; локальная правка при недоступном Git; форма → 2FA → назад → сохранение; закрытие модалки с введёнными данными. Проверка наличия кнопки в DOM не заменяет проверку результата действия.
