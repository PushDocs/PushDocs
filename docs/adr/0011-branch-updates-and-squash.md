# ADR-0011. Обновление веток и разрешение конфликтов

## Этапы работы с Git

**Статус PR/MR определяет необходимость обновления, а политика — допустимый способ.** Обновление и разрешение конфликтов меняют рабочую ветку; PR/MR остаётся открытым, целевая ветка не меняется.

## Выбор стратегии и источник настроек

`git.updateStrategy` в `.pushdocs/config.json` задаёт `merge`, `rebase` или `auto`. Используется конфиг целевой ветки PR/MR по её точному SHA. Явные `merge` и `rebase` заменяют выбор `auto`, сохраняя ограничения провайдера.

Для `auto` PushDocs получает настройки репозитория через GitLab API или GitHub API. Эти поля определяют стратегию только в режиме `auto`. Неизвестная политика блокирует запись. Пример конфига — в [справочнике](../configuration.md#обновление-веток).

## Merge: обновление и конфликты

1. PushDocs объединяет рабочую ветку с актуальной целевой. Исходные коммиты и прежние решения конфликтов сохраняются; возможен fast-forward.
2. При конфликте общий редактор показывает версии рабочей и целевой веток. Пользователь выбирает спорные фрагменты; чистые изменения обеих сторон сохраняются автоматически.
3. При расхождении веток создаётся merge-коммит с двумя родителями, и результат отправляется в рабочую ветку. Следующее обновление снова использует merge; новый конфликт возможен, если тот же текст изменился повторно.

## Rebase: обновление и конфликты

1. Коммиты рабочей ветки переносятся по одному поверх актуальной целевой. Каждый остаётся отдельным коммитом с новым SHA.
2. При конфликте операция останавливается на текущем коммите. В общем редакторе сравниваются целевая ветка с уже перенесёнными коммитами и текущий переносимый коммит.
3. «Продолжить rebase» сохраняет решение и продолжает ту же операцию; следующий коммит может потребовать нового решения.
4. После переноса всех коммитов выполняется один итоговый push. До него удалённая ветка не меняется; отмена приостановленного rebase также не меняет Git.

Поддерживается линейная история. Merge-коммиты в переносимой истории и неподдерживаемые конфликты останавливают перенос без публикации; автоматического перехода к merge нет.

## Общие правила

Стратегия едина для UI, MCP и worker и не меняется из-за нового статуса или конфликта. Черновики не включаются в обновление автоматически. Перед продолжением и отправкой проверяются права, политика и исходные SHA обеих веток; изменение входов требует нового расчёта. Уже опубликованный результат подтверждается без повторной отправки. Протокол восстановления — в [ADR-0006](0006-git-workflow.md).

## Принятие PR/MR и squash

Squash сворачивает итог PR/MR в один коммит при принятии в GitLab/GitHub и не выполняется PushDocs при обновлении ветки или разрешении конфликтов.
