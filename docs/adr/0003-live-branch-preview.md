# Живой предпросмотр ветки

Статус: принято 16 сентября 2026 года.

PushDocs запускает локальный предпросмотр при открытии раздела «Документы». Предпросмотр использует выбранную ветку, сохранённые черновики и готовые вложения. Кнопка открывает сайт по адресу `http://213.148.1.118:<port>`.

Отдельный процесс `apps/preview` управляет checkout, установкой зависимостей и Docusaurus в режиме watch. Web создаёт аренду для каждой открытой вкладки. Вкладка обновляет аренду каждые 15 секунд и освобождает её при выходе из раздела. Runner завершает процесс после последней аренды. Истёкшая аренда позволяет завершить процесс после закрытия браузера или потери соединения.

Уточнение от 1 октября 2026 года: runner хранит общий bare Git-кэш на проект и постоянный detached worktree на ветку. Путь worktree определяется проектом и веткой, а не временной сессией или портом. После импорта ветки runner готовит её файлы в фоне, по одной ветке за раз, когда нет активных сайтов. Запрос пользователя имеет приоритет над подготовкой других веток. Предпросмотр использует точный SHA, импортированный в «Документы», даже если удалённая ветка уже обновилась. Первая подготовка получает исходники сайта; Git-объекты повторно используются между ветками проекта. Существующие каталоги прежней версии переносятся с сохранением зависимостей и черновиков.

Черновики остаются в PostgreSQL. Runner переносит сохранённые изменения в файлы worktree при очередном проходе, каждые две секунды. Он записывает только изменившееся содержимое и использует атомарную замену файла. Неизменившиеся статьи и вложения сохраняют время модификации и не вызывают лишние события watcher. Пути наложенных черновиков записываются в служебные метаданные до изменения файлов, чтобы после сбоя можно было восстановить базу. При новом SHA runner сначала убирает старое наложение, обновляет исходники и применяет актуальные черновики. Зависимости и кэш сборщика сохраняются.

Установка зависимостей повторяется при изменении манифестов, lockfile, конфигурации пакетного менеджера, Yarn plugins/patches/releases, команды установки или версии Node. Изменение команды запуска или входов установки в черновиках перезапускает сайт. После выхода из «Документов» процесс останавливается, а рабочая папка остаётся. Повторный вход обычно требует только запуска команды сайта. Неиспользуемые worktree удаляются через семь дней.

Если загрузка ветки обрывается с временной ошибкой транспорта Git, runner повторяет `fetch` до трёх раз. Интерфейс показывает текущий этап запуска, включая повторную загрузку и установку зависимостей, а при сбое показывает уведомление с причиной. После перезапуска runner восстанавливает активные сессии, оставшиеся в БД со статусом `ready` или `starting`. Если аренда вкладки истекла во время деплоя, вкладка запрашивает её снова. HTTP-ответ с ошибкой не считается готовностью сайта.

Команды находятся в `.pushdocs/config.json`. Runner передаёт их в `spawn` как массив аргументов и не включает shell. Подстановки `{host}` и `{port}` разрешены только как отдельные аргументы. Docusaurus получает `0.0.0.0`, выделенный порт и `--no-open`. По умолчанию используется системный watcher без постоянного polling файлов.

По умолчанию работает один сайт; остальные запросы остаются в видимой очереди. Preview container ограничен 5 ГиБ памяти, 2 CPU и 512 процессами, без дополнительного swap. Runner проверяет суммарный RSS процессов каждого runtime UID раз в секунду и завершает запуск при превышении 4096 МиБ. Это контроль RSS, а не отдельный cgroup на сайт; жёсткий лимит памяти и CPU действует на весь контейнер. Для Node устанавливается лимит heap 1536 МиБ. Ошибки превышения памяти, установки и запуска показываются пользователю. Параметры задаются через `PUSHDOCS_PREVIEW_MAX_ACTIVE`, `PUSHDOCS_PREVIEW_MEMORY_MB`, `PUSHDOCS_PREVIEW_CONTAINER_MEMORY` и `PUSHDOCS_PREVIEW_CPUS`.

Предпросмотр исполняет JavaScript репозитория. Установка должна считать подключённые проекты доверенными. Controller получает доступ к БД, Git и хранилищу вложений, но запускает установку зависимостей и каждый активный сайт под отдельным Unix пользователем. Пользователь сайта получает свой рабочий каталог, чтение общего Git-кэша своего проекта через ACL и ограниченный набор переменных среды без секретов CMS. Он не может менять общий Git-кэш. При переиспользовании UID для другого проекта прежний ACL отзывается. Runtime может выполнять Git-запросы для метаданных Docusaurus. Runner завершает всю группу процессов, включая потомков после выхода пакетного менеджера, и отменяет незавершённые подготовки при остановке. Preview container использует init для удаления завершённых потомков и не получает Docker socket.

Caddy автоматически публикует фиксированный диапазон `43000–43019` и проксирует каждый HTTP-порт на одноимённый порт runner во внутренней Compose-сети. Сам preview-runner не публикует порты хоста. Эти endpoints не проверяют сессию PushDocs.

Уточнение от 2 октября 2026 года: остановка проверяет все процессы выделенного runtime UID, включая отделившихся от исходной группы потомков, и ждёт их завершения. Перед повторным запуском runner убирает оставшиеся процессы этого UID. Конкурирующие запросы остановки используют одну операцию завершения. Лимит heap задаётся отдельно через `PUSHDOCS_PREVIEW_NODE_HEAP_MB` и по умолчанию не растёт выше 1536 МиБ при увеличении RSS-бюджета сайта. Уведомление при завершении сайта показывает строку ошибки, а не рекламный баннер обновления Docusaurus.

Проверка пересборок выявила большой расход памяти вне heap. Основную часть буферов составляли импортированные GIF. Для стандартного запуска Docusaurus runner создаёт конфигурацию предпросмотра в runtime home. Она добавляет последний плагин с кэшем Webpack в памяти на одно поколение и отключает source maps. Исходная конфигурация сайта и зависимости остаются без изменений. Команды с явным `--config` или `-c` и другие фреймворки не меняются. Дисковый кэш зависимостей сохраняется, но Webpack не создаёт дополнительные пакеты с импортированными медиа. Сами медиа всё ещё входят в RSS процесса.

Решение меняет прежний запрет на встроенную сборку из ADR 0001 и заменённого ADR 0002 только для явно запущенного локального предпросмотра. CI preview после отправки изменений остаётся отдельной функцией и продолжает подтверждать результат конкретного коммита.
