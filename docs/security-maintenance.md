# Подготовка обновления платформы

Изменение образа Caddy подготовлено для ревью. Публикация PR не обновляет сервер.
Приложение и PostgreSQL этим изменением не обновляются.

## Caddy

Compose закрепляет выпущенный `caddy:2.11.9-alpine` по digest
`sha256:003a97808e781aa9f7e75cc2f43d34d461099031faf5e20faefb9f61126836f0`.
В индексе есть Linux amd64 для production и arm64 для локальных проверок.
Исправленный образ содержит обновлённые Go и x/net HTTP/2-парсеры.

Первичные уведомления: https://pkg.go.dev/vuln/GO-2026-6603,
https://pkg.go.dev/vuln/GO-2026-6611, https://pkg.go.dev/vuln/GO-2026-6612,
https://pkg.go.dev/vuln/GO-2026-6617.

После отдельно разрешённого rollout проверить `caddy version`, digest работающего
контейнера, HTTPS login и `/api/health`, HTTP/2 и существующие preview-маршруты.
Не считать успешную сборку или mutable tag доказательством rollout.
Сохранить предыдущий digest и установленный Compose для согласованного отката;
обычный rollback не должен незаметно возвращать уязвимый proxy.

## Ядро Ubuntu

На 26 ноября на хосте работает `6.8.0-149-generic`; целевой выпущенный security
update используемой generic-ветки — `6.8.0-151.151`:
https://ubuntu.com/security/notices/USN-9173-1.

Эти действия требуют отдельного согласованного окна и не входят в application CI:

1. Перед обслуживанием записать загруженное ядро, установленные пакеты, digest,
   состояние и рестарты шести сервисов. Убедиться в доступе к консоли провайдера.
2. Проверить актуальность серверного backup PostgreSQL/attachments и наличие
   прежнего ядра для загрузки через консоль. Не удалять старое ядро и не выполнять
   `autoremove` в этом обслуживании.
3. Установить подписанный пакет целевой Ubuntu-ветки штатным пакетным менеджером.
   Если apt предлагает другую ветку/неожиданные удаления, остановиться и пересмотреть план.
4. После отдельного разрешения перезагрузить хост. Не запускать миграции приложения
   или бизнес-проверки, изменяющие пользовательские данные.
5. Подтвердить именно `uname -r`, сервисы и healthcheck, готовность PostgreSQL,
   HTTPS login/health, `net.mptcp.enabled=0` на хосте и во всех работающих net namespaces.
6. При проблеме загрузки использовать консоль провайдера и прежнее ядро. Не откатывать
   БД или application image без отдельного основания и команды.
