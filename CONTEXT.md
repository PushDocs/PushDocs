# PushDocs

PushDocs позволяет команде редактировать документацию Docusaurus, обсуждать изменения и отправлять их на проверку через GitHub или GitLab.

## Language

**Установка (Instance)**:
Один развёрнутый сервис PushDocs с общими пользователями и подключениями, в котором могут одновременно работать несколько проектов.
_Avoid_: проект, команда.

**Владелец (Instance owner)**:
Пользователь с системным полномочием управлять установкой, общими учётными записями и подключениями. Полномочие владельца не является ролью пользователя проекта.

**Пользователь проекта (Project user)**:
Пользователь, которому предоставлен доступ к конкретному проекту с ролью администратора, редактора или читателя. У одного пользователя могут быть разные роли в разных проектах.

**Проект (Project)**:
Один сайт документации в подключённом репозитории, включая его языки, версии и наборы документов. В одном репозитории могут находиться несколько проектов.
_Avoid_: сайт как обозначение опубликованного развёртывания.

**Профиль импорта (Import profile)**:
Описание того, какие документы, языки, вложения и связанные файлы образуют проект и как их нужно изменять вместе. Профиль учитывает особенности выбранной ветки.
_Avoid_: запуск конфигурации сайта, копия репозитория.

**Связанные файлы документа (Document companion files)**:
Файлы, которые требуется согласованно изменить вместе со страницей, например запись навигации, заглушку перевода и список локализованных ссылок.
_Avoid_: вложения.

**Подключение (Provider connection)**:
Настроенный в установке доступ к конкретному экземпляру GitHub или GitLab, явно разрешённый для использования одним или несколькими проектами.
_Avoid_: пользовательская сессия, вход в CMS.

**Ветка (Branch)**:
Именованная линия изменений репозитория. Несколько веток одного проекта могут быть открыты и редактироваться независимо.
_Avoid_: версия документации, окружение.

**Версия документации (Documentation version)**:
Именованный выпуск документации Docusaurus, который может сосуществовать с другими выпусками внутри одной ветки.
_Avoid_: ветка.

**Документ (Document)**:
Страница документации в определённой ветке, наборе документов, языке и версии. Переименование страницы не создаёт новый документ, если связь с прежней страницей установлена однозначно.
_Avoid_: коммит, черновик.

**Набор изменений (Change set)**:
Общая для пользователей проекта совокупность ещё не отправленных в Git изменений одной ветки. Набор включает создание, изменение, перемещение и удаление документов и вложений.
_Avoid_: PR, MR, ветка.

**Черновик (Draft)**:
Сохранённая в PushDocs редакция документа, которая ещё не вошла в коммит репозитория.
_Avoid_: опубликованный документ.

**Снимок предпросмотра (Preview snapshot)**:
Состояние файлов выбранной ветки с сохранёнными черновиками и вложениями на момент запроса предпросмотра. Последующие изменения документов не меняют этот снимок.
_Avoid_: публикация сайта, коммит.

**Живой предпросмотр ветки (Live branch preview)**:
Локально запущенный сайт выбранной ветки с сохранёнными черновиками и вложениями PushDocs. Процесс работает, пока хотя бы у одного пользователя открыт раздел «Изменения», и обновляет сайт при сохранении новых правок.
_Avoid_: снимок предпросмотра, CI preview, публикация сайта.

**Запрос на слияние (Change request)**:
Предложение перенести изменения из исходной ветки в целевую. В GitHub называется pull request (PR), в GitLab называется merge request (MR).
_Avoid_: набор изменений, публикация сайта.

**Готовность к слиянию (Merge readiness)**:
Состояние запроса на слияние, полученное от Git-провайдера с учётом его условий слияния. Успешные проверки сами по себе не означают готовность: могут требоваться одобрения, разрешение обсуждений или устранение конфликтов. Недоступный статус не считается готовностью.

**Одобрение (Approval)**:
Действующее решение ревьюера у Git-провайдера. Отозванные решения не входят в число одобрений; требование изменений показывается отдельно. PushDocs отображает эти решения и комментарии к MR/PR только для чтения.

**Конфликт (Conflict)**:
Несовместимые изменения одного содержимого или пути, для которых пользователь должен выбрать итоговый результат. Конфликт может возникнуть при сохранении черновика, обновлении ветки или подготовке слияния.

**Обсуждение (Discussion)**:
Цепочка комментариев к документу, его фрагменту или запросу на слияние. Обсуждение внутри PushDocs и обсуждение у Git-провайдера имеют явно указанный источник.

**Непрочитанный комментарий (Unread comment)**:
Комментарий PushDocs к выбранному документу и ветке, написанный другим пользователем и ещё не отмеченный прочитанным текущим пользователем. При открытой панели в активной вкладке загруженные комментарии отмечаются прочитанными. Состояние сохраняется на сервере для каждого комментария и пользователя и обновляется через канал событий.

**Проверка (Check)**:
Результат автоматической проверки определённой ревизии запроса на слияние. Проверка может выполняться на коммите исходной ветки или на временном результате слияния.

**Вложение (Attachment)**:
Файл или изображение, загруженные для использования в документации. Загрузка в черновик и отправка вложения в репозиторий являются разными действиями.

**Пользовательский компонент (Custom component)**:
Компонент документации, который разработчик определяет в проекте, а редактор вставляет в документ и настраивает через доступные свойства.
_Avoid_: компонент интерфейса PushDocs.
